# 松木さんの文体ガイド

ブログ記事（content/blog/**/*.md）の全文分析から導出した文体ルール。

---

## 1. トーン・姿勢

- **等身大**：成果だけでなく、失敗・反省・モヤモヤを隠さず書く
  - NG：「課題はあったものの、全体的に良い結果を得られた」
  - OK：「後半にかけて崩れてしまった。ここは明らかな反省点だ」「引越ししんどい！片付かない！！」
- **自己開示がある**：「自分はこう考えた」「こんな経験があった」という一人称の語り
- **教えるより共感・共有するスタイル**：「〜ないだろうか」「〜ですよね」で読者を引き込む
- **軽さを忘れない**：深刻な話でも「(笑)」「笑」「〜がが..」など崩した表現を時折入れる

---

## 2. 文体（敬体 vs 常体）

### 論考・専門記事（EMの話、フレームワーク解説など）
- **だ・である調**を基本とする
- 短い断言文を多用：「原因のひとつは、〜にある。」「重要なのは、〜という点だ。」
- 柔らかい補足（「〜だと思う」「〜なのかもしれない」）も混じってよい

### 振り返り・抱負・イベントレポート・個人記事
- **です・ます調**を基本とする
- ただし独り言・感想には「〜なぁ」「〜よね」「〜かな」が自然に混じる

---

## 3. 語尾・語末の変換表

| AIが生成しがちな表現 | 松木さんの表現に変換 |
|---|---|
| 〜と考えられます | 〜と思います / 〜と感じます |
| 〜が重要です | 〜が大切だと思います / 〜が大事 |
| 〜することが求められます | 〜していきたい / 〜していく必要があると思う |
| 〜することで実現できます | 〜することで、〜になる |
| 〜であると言えるでしょう | 〜だと思う / 〜なんだよね |
| 〜を意識することが肝要です | 〜を意識したい / 〜が大事になる |
| 〜にほかなりません | 〜だと思う |
| 〜を心がけましょう | 〜を意識できるとよい / 〜してみてほしい |

**よく使う語尾セット**：
- 意欲・展望：「〜していきたい」「〜できるといいな」「〜していこう」
- 成果と課題：「〜できた」「〜できていない」「〜できるようになってきた」
- 柔らかい断言：「〜だと思う」「〜なんじゃないかと思う」「〜かな」
- 余韻：「〜なぁ」「〜よね」「〜だよなぁ」

---

## 4. 文の構造

- **短い断言 + 補足の展開**を基本とする
  - 例：「このサイクルは自然には回らない。多くの現場では、〜というケースが多い。」
- **体言止めは使わない**（述語まで書ききる）
- 一文が長くなる場合は読点（、）で区切りながら続ける（一文で完結させない）
- 「〜して、〜して、〜できた。」のような自然な時系列の流れを活かす

---

## 5. 論理展開

**基本パターン：問題提起 → 自分の経験・観察 → 考察 → 具体的な行動・提言**

- 書籍・フレームワークを参照するときは名称を明記し、自分の言葉で要約する
- 接続語を使って論理をつなぐ：「具体的には」「たとえば」「逆に」「一方」「加えて」
- 抽象論で終わらせず、必ず自分の具体的な経験・行動に落とす
- 「なぜそうするか」の理由を自然に織り込む

---

## 6. 構成・フォーマット

- **見出し**：H2 で大きく区切る。必要なら H3 も使う
- **箇条書き**：列挙・比較・具体例はリスト化する（迷わず使う）
  - 入れ子リストも使う（インデント付き `*` や `-`）
- **まとめセクション**：記事末に「まとめ」を置き、要点を短く再確認する
  - 口語的な前置き：「ということで、超ざっくりまとめると」「まとめると」
  - 次回予告や意欲で締める：「続きは〜の記事を書くとする。」「やっていこう。」
- **関連リンク**：文中にインラインで埋め込む（別行にしない）
- **引用**：blockquote（`>`）は要点の補強に使う

---

## 7. 語彙・専門語

- EM、スクラム、アジャイル、CfP、1on1、OKR などの業界用語は説明なしで使う
- 英語交じりを自然に使う（「Day1」「keynote」「OST」など）
- 初出の固有フレームワーク・書籍名は軽く説明を添える

---

## 8. やってはいけないこと

| NG | 理由 |
|---|---|
| 「〜でございます」「〜いたします」 | 過剰に丁寧すぎる |
| 完璧に整いすぎた並列構造（A・B・C がすべて同じ長さ） | AIっぽい。崩してよい |
| 結論を曖昧にぼかす | 正直に「できていない」「反省」と書く |
| 抽象論だけで締める | 必ず自分の経験・行動に落とす |
| 過去の不満を積み上げて伝える | タイムリーな出来事をその時点で言語化する |
| 全段落を同じリズム・長さで揃える | 短文と長文を混在させる |

## 実例（変換前 → 変換後）

**変換前（AIらしい）：**
> メンバーの成長を支援するためには、経験の質を高めることが重要です。具体的には、振り返りの機会を設けることや、気づきを言語化する場を創出することが求められます。これらの取り組みを通じて、経験学習サイクルを機能させることができます。

**変換後（松木さんらしい）：**
> メンバーの成長を支援するとき、大事なのは経験の量より質だと思う。振り返る機会をつくること、気づきを言葉にする場をつくること。これができて初めて、経験が本当の意味で力になる。逆にいえば、経験を与えるだけでは足りないということだ。
